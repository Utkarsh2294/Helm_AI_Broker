These reports distinguish observed results from targets. Earlier measurements are retained.

The light theme remains light under OS dark mode. Scoped semantic text colours, badges, headings and controls were corrected after actual contrast/heading findings. Axe 4.14.0 reports no WCAG 2 A/AA, 2.1 AA or 2.2 AA violations across login, six workspace routes and an open fact-find. The initial authenticated queue JavaScript totals 198.59 KB gzip. Security, case, audit and governance views load separately. Production Compose serves a built preview without development HMR; its `web` hostname is explicitly allowed on the private network. Production scripts use a same-origin CSP with no inline JavaScript. The current inline-style allowance supports existing React styling; a nonce/strict-dynamic deployment is not claimed. HSTS is enabled for the configured live HTTPS environment rather than local HTTP. TLS termination, host policy and external header validation remain deployment work.

The final PostgreSQL measurement used 1,117 fictional cases. Ten concurrent filtered queue requests have p95 207.19 ms; 20 concurrent ranking submissions have p95 425.40 ms; insights p95 is 95.54 ms. The stronger 50-concurrent unfiltered queue scenario is 1,829.40 ms. Fifty established SSE clients receive the event at p95 321.23 ms, including the initiating assignment request: the 200 ms target is **not met**. Detail reads now process only their own due jobs and authentication/audit queries use fewer SQL round trips. The benchmark expires its own idle connections before Uvicorn's five-second timeout to avoid stale-socket races between batches; it does not retry or remove slow samples. Production capacity acceptance requires representative Linux/staging measurement.

The shipped Python dependency scan still reports four distinct ChromaDB advisories (eight raw duplicate entries), without listed fixed versions. Setuptools was upgraded to 84.1.0 in both build definitions. No ChromaDB server is exposed and model memory is disabled, but no advisory is silently suppressed. Frontend audit has zero vulnerabilities; Bandit has zero medium/high findings. CI also runs pinned Semgrep and Trivy, with failing exit codes for findings. Newly configured CI scanners are not represented as locally executed scans. Trivy action v0.36.0 is pinned to its resolved commit and CLI v0.76.1, verified against the [official action release](https://github.com/aquasecurity/trivy-action/releases/tag/v0.36.0) and [CLI release](https://github.com/aquasecurity/trivy/releases/tag/v0.76.1).

Host-port and startup attempts that failed are not scan passes. The report records the actual scope; it is not an independent staging penetration test or an active scan.
