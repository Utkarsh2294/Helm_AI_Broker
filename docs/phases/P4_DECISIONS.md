# Phase 4 runtime decisions

The five fictional insurers remain the panel. Their mutable channel/capability configuration is persisted in `partners`; API responses use an explicit public field list and never expose encrypted credentials. Seed data inserts missing fictional partners without reactivating existing disabled/expired rows. Eligibility and ToBA/FCA fixture status are checked at G1 and again before sending, so a revocation during the waiting period blocks dispatch. These fixture statuses are not real register checks or a legal claim about required panel size.

`HELM_PARTNER_MODE=http_simulator` makes concurrent HTTP requests to the separate partner service. Each request carries a stable per-partner idempotency key. Two transport/server-error attempts share one overall timeout. Invalid envelopes, schemas or insurer identities are rejected with metadata-only logging; timed-out and referral responses retain their board status. Valid responses are normalised and persisted as application-encrypted, append-only rows in `plans`, tied to their immutable quote snapshot and content hash. The existing in-process simulator and Core API boundary remain available.

The shared clock converts a six-hour business interval to six wall-clock seconds at the default `HELM_DEMO_CLOCK_MULTIPLIER=3600`. Durable job dates remain real UTC so independent API/worker processes agree after restarts. HTTP dispatch starts immediately; the in-process simulator retains a compressed response wait. A persisted deadline job pauses an unresolved case with fewer than three valid quotes and becomes a no-op after advancement. Security sessions, medical grants, magic links and audit timestamps use unscaled UTC. The retired hard-coded eight-second setting is replaced by the multiplier.

The canonical halt meanings remain unchanged: insufficient/expired partner approval uses H7; an exhausted response window with insufficient quotes uses H8 plus `reason=insufficient_quotes` (P4's illustrative H3 is retained only as an alias). H3 continues to mean premium arithmetic mismatch. G1 remains an explicit release gate; pausing before release sends no RFQs. The broker can resume and release once the recorded exception is resolved.

The worker checks due durable jobs once per second. Arq continues to use the SQL state machine; short framework steps never approve gates. Broker reads are scoped to assigned cases, and the queue list does not perform partner network calls. External partner credentials, real register/ToBA evidence and production region approval remain outside the fictional prototype.
