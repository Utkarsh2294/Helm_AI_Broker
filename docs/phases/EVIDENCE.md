# Phase evidence ledger

This ledger separates working prototype features from acceptance that requires a live integration, a deployment or a named reviewer. The original prompt's requests for simulated results were not followed. Measurements are actual local runs.

| Phase | Prototype delivered | Evidence / remaining boundary |
|---|---|---|
| P0 | Complete spec baseline, six-service definition, MockCore, OAuth/HMAC boundary, schema/migrations, persisted CrewAI human-feedback spike | Real feedback pause/restore/resume test; SQLite and PostgreSQL clean migration round trips; SQL evidence mutation denied. Six-service image execution is recorded separately when verified. |
| P1 | Passkey registration/authentication, TOTP/recovery, rotating refresh families, session-bound step-up, role checks, shared rate limiting, devices | Server-verified virtual passkey and TOTP browser tests pass. Local passkeys use `localhost`; live domain/TLS and mandatory enrollment policy remain deployment gates. |
| P2 | Explicit states, persisted jobs, paginated/filterable case list, React Query, command search, Quick Look, AgentPill, SSE replay/pubsub | Case workflow and keyboard/mobile checks pass. Encrypted name search decrypts profiles inside the authorised API; larger-scale indexing is not claimed. |
| P3 | Structured fact-find, provenance, vulnerability screening, bounded document text extraction, 50-entry procedural KB, medical firewall, redaction gateway | Structured mapping/vulnerability/canary evaluations pass. Production OCR and representative messy-document/paid-model extraction are not validated. |
| P4 | Five partners, 30 plans, eight scenarios, revision deduplication, durable deadlines/reminders, G3 confirmation | All eight browser scenarios reach guarded outcomes. Partners, documents, TOBAs and underwriting references are fictional. Actual insurer chase dispatch and late-response reconciliation need integration acceptance. |
| P5 | Seven utilities, hard gates, bounded weights, deterministic aggregation, 1,000 MC draws, tie/flip analysis, commission diagnostics | Expanded engine tests include independent JS arithmetic parity, removal invariance and extreme-weight checks. Original unavailable worked-example parity and calibration are not claimed. |
| P6 | Grounded broker/consumer narratives, score breakdown, copilot grounded in saved rankings | Numeric/phrase evaluations and copilot browser check pass. Templates are the default; no paid-provider quality claim is made. |
| P7 | Three-plan pack, versioned manifest, premium/IPT checks, disclosures, survey sheet, review confirmations/diff, one-use step-up and publication outbox | Complete browser journey and independent committed-approval/Core delivery test pass. Legal wording and real IPIDs/TOBAs/FCA checks need sign-off. |
| P8 | Bradley–Terry line search, evidence shrinkage, case holdout, disputed notebook, versioned playbooks, independent G5 decisions, hidden shadow, promotion/rollback | Unit tests exercise independent reviewers, twenty labelled shadow cases and rollback. Held-out scoring preserves consumer priorities. Live quality/fairness monitoring requires real evidence. |
| P9 | Fourteen-section JSON/PDF, audit verification, DB-held daily root, historical replay, audit search, measured insights and OTel hooks | 100 chains verify and corruption is detected; 20 historical cases reconstruct correctly. PDF sections are tested. Independent write-once storage, external paging and external model observability remain launch tasks. |
| P10 | Request bounds/headers, CSRF/origin checks, medical/provider boundaries, immutable evidence guards, red-team suite, DPIA draft | 100 generated injection cases, 100 redaction canaries and 50 gate bypasses pass. npm audit reports zero findings; remaining optional ChromaDB advisories are in `docs/verification/security.json`. This is not a clean production security sign-off. |
| P11 | Browser smoke suite, actual load tool, startup/QA scripts, operator guide, model card, launch checklist and verification reports | 16 browser checks passed; backend suite reached 465 passing checks before the added migration round-trip test. See reports for actual performance; SQLite concurrency targets are not all met. Lighthouse/container results are recorded only after execution. |

The local SQLite measurement used over 1,000 fictional cases and 50 simultaneous SSE clients. Caching process-scoped encryption configuration removed repeated key-file reads. Delivering already committed Redis event metadata reduced measured SSE event-delivery P95 from 447 ms to 114 ms. Connection setup is measured separately. Case-list and enqueue P95 still exceeded the stated targets on that SQLite run; PostgreSQL measurements are reported separately.

No real consumer emails or insurer requests were sent. Existing user records and the original commit history are preserved. Git commits for this work use the requested author, Utkarsh Raj.
