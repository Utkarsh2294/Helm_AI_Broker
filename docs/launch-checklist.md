# Live launch gates

This repository is a working fictional prototype. These gates require deployment evidence and named owners.

- [ ] DPO approves the DPIA, purposes, lawful bases, special-category conditions and supplier contracts.
- [ ] Compliance verifies adviser authorisation, policy wording, cancellation, search basis, insurer mappings, IPIDs and TOBAs.
- [ ] Consumer/Core teams verify real OAuth scopes, webhooks, idempotency, accepted payloads and delivery outcomes.
- [ ] Staff MFA is mandatory, recovery is operated securely and passkeys are tested on supported devices.
- [ ] Secrets are replaced, TLS and secure cookies are verified, database privileges and network access are restricted.
- [ ] LLM providers, if enabled, have verified processing locations, contracts, redaction evaluation and monitored budgets.
- [ ] Real OCR and unstructured extraction are evaluated with representative documents and low-confidence routing.
- [ ] Independent security review triages dependency advisories, permission boundaries, injection and data-export paths.
- [ ] External write-once audit roots, independent alert delivery and an on-call rota are exercised.
- [ ] Approved retention, legal holds, deletion, backup expiry, key rotation and recovery procedures are tested.
- [ ] Complaint owner and response timetable are confirmed; external communications and referral wording are reviewed.
- [ ] Representative load, accessibility, mobile-device and end-to-end Core delivery acceptance is signed off.
- [ ] Compliance signs the model card and governance policy; real calibration and outcome monitoring are assigned.

See the phase evidence ledger for local measurements. A passing test or a demonstration identifier is not a live authorisation.
